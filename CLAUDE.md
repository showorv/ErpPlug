# ErpPlug — rules for all code in this repo

Source of truth: `docs/BRD.pdf` (requirements and architecture) and `docs/build-plan.pdf` (phases, scope cut, work split).
When a task names a BRD section (for example "BRD 9.3"), read that section before writing code.

## Never break these

- Every business table has a non-null `tenant_id` and an RLS policy. No exceptions.
- Business code never imports the raw Prisma client. Use the tenant-scoped client from `kernel/tenancy`.
- No raw SQL outside the kernel helper that sets the tenant.
- A module imports another module only through its `contracts/` folder, and only if listed in `requires` or `optional` in its manifest.
- The kernel never imports from `modules/`.
- Cross-module links are stored as IDs. No foreign keys across module schemas unless the target is in `requires`.
- "When X happens in A, B does Y" is an event subscription in B, never a call from A.
- Routes, permissions, events, settings, queue names and cache keys start with the module key.
- Modules never read plans, prices or invoices. Ask the entitlements service.
- Kernel Billing (our fees) and the Accounting module (tenant's books) share no tables and no code.

## Conventions

- No credentials in committed files, not even local dev ones. They live in the git-ignored `.env`, generated by `pnpm setup:env` from `.env.example` (which leaves secrets empty). GitGuardian scans every PR.
- API: `/api/v1/{module}/...`, shared pagination, filter, sort and error format from `packages/contracts`.
- Every controller action declares its permission with a decorator.
- New module = copy `modules/notes` and rename.
- Every pull request adds or updates tests; a new table must pass the isolation suite.
- All tenant-facing UI strings (`apps/web`, module `web/` folders) go through translation files from day one (Bangla comes right after the pilot). The operator console `apps/admin` is internal and English-only.
- Contracts first: request/response types land in `packages/contracts` in a small PR before the endpoint or screen is built.
- List endpoints declare their query with `defineListQuery` (contracts) and parse it with `ListQueryPipe`; list screens use `DataTable` + `useListQueryState` from `packages/ui`. See `packages/contracts/README.md`.
- Screens use `packages/ui` components and theme tokens (`bg-background`, `text-muted-foreground`), never raw palette colours. The live reference is the admin UI kit page (`/ui`).

## Git workflow

- `main` only changes through reviewed pull requests. Never push to `main` directly.
- Showrov works on the `showrov` branch; Uday on his own branch.
- Before starting work: `git fetch origin && git merge origin/main` into your branch (merge, don't rebase a pushed branch).
- Only one open pull request may add a Prisma migration at a time; announce it before starting.
- One ADR in `docs/adr/` per irreversible choice.

## Commands

- `pnpm install` — install everything
- `pnpm dev`, `pnpm build`, `pnpm lint`, `pnpm typecheck`, `pnpm test` — run across the workspace via Turborepo
- `pnpm format` / `pnpm format:check` — Prettier
- `pnpm infra:up` / `infra:down` / `infra:reset` / `infra:ps` / `infra:logs` — local Docker services (see `infra/README.md`)
- `pnpm setup:env` — create `.env` with random local passwords (once per machine)
- `pnpm --filter @erpplug/api dev` (or `@erpplug/web`, `@erpplug/admin`) — run one app only
- Dev URLs: API http://localhost:3000 (Swagger at /api/docs), web http://localhost:5173, admin http://localhost:5174; the worker (no HTTP) starts with `pnpm dev` too
- Coming in Phase 0: `pnpm db:migrate`, `pnpm test:isolation`

## Stack notes

- NestJS 12 is ESM-only; `apps/api` compiles to CommonJS and loads it via `require(esm)` (Node 22.12+). Check https://docs.nestjs.com/llms.txt before relying on older Nest knowledge.
- TypeScript is pinned to 6.0.x because typescript-eslint does not support 7 yet.
- Tests run on Vitest everywhere: SWC (`unplugin-swc`) in `apps/api` for decorator metadata, jsdom + Testing Library in the React apps.
- React Router 8: `RouterProvider` comes from `react-router/dom`, everything else from `react-router`; `react-router-dom` no longer exists.
- React apps call the API with relative `/api/...` paths; Vite proxies them to the API in development.
- CI (`.github/workflows/ci.yml`) runs format check, lint, typecheck, test and build on every PR. GitHub Actions are pinned to commit SHAs.
- Background jobs: BullMQ 6 with ioredis in `apps/worker` (a NestJS app without HTTP). Queue and job names start with the module key; the worker's tests need Redis (`pnpm infra:up`; CI runs a Redis service).
- Object storage is RustFS (S3-compatible) because MinIO stopped publishing its free Docker image. Code uses the AWS S3 SDK only.
